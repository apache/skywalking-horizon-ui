# 1.2.0

## Layers

### Features

**The OTLP gateway layer is hidden from the sidebar by default, like the agent one.** OAP 11.2.0 draws a gateway listed in its `gateways.yml` under `OTLP_VIRTUAL_GATEWAY` when the gateway's callers and callees report OTLP traces, where it used `VIRTUAL_GATEWAY`. The layer has no dashboard, so `layers.excluded` now hides it by default, next to `FAAS` and `VIRTUAL_GATEWAY`; the gateway still shows as a node in the topology. A `horizon.yaml` that sets its own `layers.excluded` list keeps it: add `OTLP_VIRTUAL_GATEWAY` there to hide the layer too. See [Configuration File](../setup/horizon-yaml.md#excluded-layers).

**The OAP layer's alarm delivery widgets show the gRPC alarm hook.** OAP 11.2.0 also counts the deliveries of its gRPC alarm hook, as the channel `gRPC`, so **Alarm Delivery / min** and **Alarm Delivery Latency (ms)** show it as one more line without a template change. gRPC has no HTTP status, so **Alarm Delivery Responses / min** now shows only once an HTTP hook has answered, and stays hidden on a node that only uses the gRPC hook. An OAP that already stores this layer's template and translations keeps the old Responses condition and tips; to adopt them, open **Dashboard setup → Layer dashboards → OAP**, choose **Reset to → Bundled** and **Check diff & push**, then do the same for each language on the **Translations** page.

## Traces, logs and events

### Features

**The Zipkin and TraceQL trace tabs take tags the way the native Traces tab does.** The Zipkin tab's **Annotations** field and the TraceQL builder's **Tag** field are now the same field as the native tab's **Tag**: type `key=value` (on Zipkin, also a bare annotation such as `error`), pick from the suggestion list, press Enter, and the term joins a row of removable chips under the form — **Active tags**, or **Active annotations** on Zipkin. Only the chips reach the query. On Zipkin, several terms typed at once with ` and ` become one chip each. The TraceQL builder's key and value box pairs and the **+ Tag** button are gone. The field comes last on both, on a row of its own with its chips under it: on Zipkin, **Limit** and **Time range** now share the duration row.

**A trace opens to its logs.** Every trace detail has a **Logs** button that opens a box over the trace listing the stored log lines carrying its trace id, oldest first, 50 to a page — on the native, Zipkin and TraceQL trace tabs, on Trace inspect, and on the trace overlay a log row or a link opens. A span's detail adds a **Related logs** button, which lists only the lines that span wrote: a native span's by its segment id and span id, on any OAP; a Zipkin or OTLP span's by its hex span id, from SkyWalking 11.2 — against an older OAP the button is disabled and says what it needs. Nothing is read until the box opens. The lines are searched from 5 minutes before the trace's first span to 5 minutes after its last, at most the trace's last week. Lines from services your role cannot read are left out, and the box says how many. A line is found only if it was stored with the trace id — set by a SkyWalking agent's log reporter, by OAP 11.2 from an OpenTelemetry log record's own trace id and span id, or extracted by a LAL rule. See [A trace's logs](../operate/traces.md#a-traces-logs).

**A log line opens its trace from the right store.** A log row's **↗ trace** link reads the trace from its layer's own trace store — Zipkin on a Zipkin layer, OTLP (through TraceQL) on a layer whose traces are OTLP, the SkyWalking store otherwise — and on **Log inspect** from the store of the picked service's layer (OTLP for a service of **OTLP Service**). When the SkyWalking store holds no spans for the id, the trace overlay offers to query it from the **zipkin** or **traceql-otlp** store instead, where it used to stay empty.

**Click a service in a trace's legend to highlight its spans.** In every trace detail — native, Zipkin and TraceQL, on the trace tabs, on Trace inspect and on the trace overlay — the service legend above the spans now picks a service: its waterfall rows, Tree nodes and Statistics rows take its color, and the first of them is brought into view. The highlight stays while you switch layouts; click the service again, or open another trace, to clear it.

**The tag field says when something you typed did not make it into the query.** On the native, Zipkin and TraceQL builder trace tabs, pressing Enter on text that is not `key=value` (or, on Zipkin, a bare annotation) leaves it in the field and covers the field with a red note saying so, where it used to be dropped or added without a value. Clicking **Run query** with a tag still in the field runs without it and covers the field with a note for five seconds: press Enter to add it. Typing, or clicking the note, takes it away.

### Fixes

**The tag fields on the Traces, Logs, Trace inspect and Log inspect pages leave input-method keys to the input method.** Confirming a Chinese, Japanese or Korean candidate with Enter used to add the half-composed text as a tag, and the arrow keys moved through the tag suggestions instead of the candidates.

**A tag value holding a comma keeps its suggestions on the Traces and Logs tabs.** Typing `db.statement=SELECT a, b` used to switch the suggestions back to tag keys after the comma, as if a second tag had started; the field now completes the whole text as one tag. Trace inspect and Log inspect, whose field takes a comma-separated list, are unchanged.

## Alarms

### Fixes

**The Layer, Service, Instance and Endpoint filters on the alarm pages open a readable list.** On Windows, the browser drew their open list white with near-white text, on the default alarm page and on every configured one. They are now the same dropdown the Traces tab's pickers use: a dark list with a filter box to type into. ([apache/skywalking#14211](https://github.com/apache/skywalking/issues/14211))
