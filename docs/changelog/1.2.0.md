# 1.2.0

## Layers

### Features

**The OAP node dashboard is split into four tabs, and charts the traffic between OAP nodes.** The OAP layer's node dashboard now groups its widgets under **Receivers & JVM**, **Persistence & Storage**, **Aggregation & Cluster** and **Query & Alarms**; it opens on **Receivers & JVM**, and only the open tab's widgets are read from OAP. **Aggregation & Cluster** adds five widgets for OAP 11.2.0+, which read `no data` against an older OAP: **Cluster Size** — the latest count, above its line; **Cluster Remote Traffic / min** — messages sent to peers, sent locally and received, with send errors, receive errors and messages for a worker the node does not have on a second axis; **Cluster Remote Send Latency p99 (ms)** — one line per peer, for the five slowest; **Cluster Remote Streams** — gRPC streams in flight, and the time spent waiting for a free stream slot; and **Cluster Remote Send Queue (%)** — one line per peer, for the five fullest. Every widget on the dashboard now shows whether or not it has data: the three alarm delivery widgets used to stay hidden until the node had delivered an alarm, and now read `no data` until then. Only **BanyanDB Write Latency (ms)** and **Elasticsearch Write Latency (ms)** still show just for the storage backend in use. An OAP that already stores this layer's template and translations keeps the single grid. To adopt the tabs, open **Dashboard setup → Layer dashboards → OAP**, choose **Reset to → Bundled** and **Check diff & push**. The translations stored for the old grid are then left over, and the **Translations** page makes a language that carries leftovers read-only: open the OAP layer there, choose **Remove them → All languages**, then **Reset to → Bundled** and **Check diff & push** for each language. See [SO11Y_OAP — Aggregation & Cluster](../dashboards/so11y_oap.md#aggregation--cluster).

**A line widget can show a big number with its line.** A line widget can show one number — the average, the latest, or the latest non-null value of its series — together with the line. Set it with the **Number** controls on a line widget in the Layer dashboards editor, or `showValue` in the template. **Stacked** puts the number at the top and draws its line below as a bare trend scaled to its own range, so a small change stays visible; **Axes** turns the axes on, and **Top margin (px)** sets the space kept for the number — a small margin lets the line run faintly behind it. **Side by side** puts the number on the left and the line chart, with its axes, on the right; **Number width (%)** sets the split, 35% by default. Latest is the range's last bucket even while it is still empty; latest non-null is the value MQE's `latest()` returns. See [Dashboard widgets → A number with the line](../components/dashboard-widgets.md#a-number-with-the-line-showvalue).

**The Kubernetes cluster dashboard's inventory cards show their trend.** **Node Total**, **Namespace Total**, **Deployment Total**, **StatefulSet Total**, **DaemonSet Total**, **Service Total**, **Pod Total** and **Container Total** show the same latest count as before, now with the count over the picked range below it, so a node lost or a burst of pods reads at a glance. An OAP that already stores this layer's template keeps the plain cards; to adopt them, open **Dashboard setup → Layer dashboards → Kubernetes**, choose **Reset to → Bundled** and **Check diff & push**. See [Kubernetes](../dashboards/k8s.md).

**The OTLP gateway layer is hidden from the sidebar by default, like the agent one.** OAP 11.2.0 draws a gateway listed in its `gateways.yml` under `OTLP_VIRTUAL_GATEWAY` when the gateway's callers and callees report OTLP traces, where it used `VIRTUAL_GATEWAY`. The layer has no dashboard, so `layers.excluded` now hides it by default, next to `FAAS` and `VIRTUAL_GATEWAY`; the gateway still shows as a node in the topology. A `horizon.yaml` that sets its own `layers.excluded` list keeps it: add `OTLP_VIRTUAL_GATEWAY` there to hide the layer too. See [Configuration File](../setup/horizon-yaml.md#excluded-layers).

**The OAP layer's alarm delivery widgets show the gRPC alarm hook.** OAP 11.2.0 also counts the deliveries of its gRPC alarm hook, as the channel `gRPC`, so **Alarm Delivery / min** and **Alarm Delivery Latency (ms)** show it as one more line without a template change. gRPC has no HTTP status, so **Alarm Delivery Responses / min** reads `no data` on a node that only uses the gRPC hook. An OAP that already stores this layer's template and translations keeps the old tips; to adopt them, open **Dashboard setup → Layer dashboards → OAP**, choose **Reset to → Bundled** and **Check diff & push**, then update the translations as the four-tab entry above describes.

**The OTLP Service layer has a Logs tab.** SkyWalking 11.2 keeps the logs of the OpenTelemetry services that set `service.layer=OTLP_GENERAL`, which earlier releases dropped, so the bundled template now turns the layer's Logs tab on: it lists the picked service's stored logs, and a row carrying a trace id opens its trace. Against an earlier OAP the tab stays empty. An OAP that already stores this layer's template keeps the tab off; to adopt it, open **Dashboard setup → Layer dashboards → OTLP Service**, choose **Reset to → Bundled** and **Check diff & push**. See [OTLP Service](../dashboards/otlp_general.md#traces-and-logs).

**The OAP node dashboard follows the trace receivers' per-span metrics.** OAP 11.2.0 counts the trace receivers' self-observability metrics per span, for SkyWalking agents, Zipkin and OTLP alike, so on the **Receivers & JVM** tab **Trace Analysis / min** is now **Trace Spans Analyzed / min**, and **Trace Analysis Latency (ms)** is now **Trace Analysis Latency (ms / 1k spans)**, the milliseconds 1,000 spans take. **Zipkin Spans Dropped** is now **Trace Spans Dropped / min**: the spans the Zipkin and OTLP receivers received but did not store, by protocol and reason (`sampled`, `rate_limited`, `store_failed`, `process_failed`). **OTEL Received** is titled per minute, as its values always were, and gains a **spans rejected** line for the OTLP spans whose resource names no service. An OAP that already stores this layer's template and translations keeps the old widgets; to adopt them, open **Dashboard setup → Layer dashboards → OAP**, choose **Reset to → Bundled** and **Check diff & push**, then update the translations as the four-tab entry above describes. See [SO11Y_OAP — Receivers & JVM](../dashboards/so11y_oap.md#receivers--jvm).

### Fixes

**Previewing a layer draft follows its log settings.** In **Dashboard setup → Layer dashboards**, a previewed draft's Logs tab used the published template's log scope — or the service scope, for a layer OAP does not list yet — rather than the draft's. The preview now uses the draft's log scope and log type.

**A tab widget's charts stack on a narrow screen.** Below 1100 px wide, the charts inside a layer dashboard's tab widget now take the full width like every other widget, where they stayed side by side, and the tab box grows to fit them. See [Dashboard widgets → tab](../components/dashboard-widgets.md#tab).

**The Translations page previews a tab widget's charts.** The preview drew a layer dashboard's tab widget as one "No preview for this widget kind." box, so the charts in it could not be clicked to translate. It now draws the tabs and their charts: clicking a chart opens that chart's fields, and clicking a tab name opens the widget's title and tab names.

**A line chart's time labels move with each refresh.** On a rolling time range a refresh updated a line chart's values but kept its earlier time labels, so hovering a point named a minute other than the one it was read for; the labels now move with the values.

**A line chart of whole numbers steps its axis by whole numbers.** A line widget with `format: "int"` — pod counts, replicas, node counts — printed its rounded half-step ticks twice on a small range (3, 3, 2, 2, 1, 1, 0); its axis now steps 0, 1, 2, 3.

**Turning off a component, or deleting a page, counts the charts inside tab widgets.** In the Layer dashboards editor, the confirmation counted a tab widget as one widget however many charts it held; it now counts the charts.

**The Redis node dashboard's Avg Command Time is in microseconds.** OAP 11.2.0 fixes `meter_redis_instance_average_time_spent_by_command`, which showed 0 or 1 for every command, and reports it in microseconds, so the node dashboard's widget is now titled **Avg Command Time (microseconds)**. Against an older OAP it still shows 0 or 1. An OAP that already stores this layer's template and translations keeps the old title; to adopt the new one, open **Dashboard setup → Layer dashboards → Redis**, choose **Reset to → Bundled** and **Check diff & push**, then do the same for each language on the **Translations** page. See [Redis](../dashboards/redis.md).

## Traces, logs and events

### Features

**The Zipkin and TraceQL trace tabs take tags the way the native Traces tab does.** The Zipkin tab's **Annotations** field and the TraceQL builder's **Tag** field are now the same field as the native tab's **Tag**: type `key=value` (on Zipkin, also a bare annotation such as `error`), pick from the suggestion list, press Enter, and the term joins a row of removable chips under the form — **Active tags**, or **Active annotations** on Zipkin. Only the chips reach the query. On Zipkin, several terms typed at once with ` and ` become one chip each. The TraceQL builder's key and value box pairs and the **+ Tag** button are gone. The field comes last on both, on a row of its own with its chips under it: on Zipkin, **Limit** and **Time range** now share the duration row.

**A trace opens to its logs.** Every trace detail has a **Logs** button that opens a box over the trace listing the stored log lines carrying its trace id, oldest first, 50 to a page — on the native, Zipkin and TraceQL trace tabs, on Trace inspect, and on the trace overlay a log row or a link opens. A span's detail adds a **Related logs** button, which lists only the lines that span wrote: a native span's by its segment id and span id, on any OAP; a Zipkin or OTLP span's by its hex span id, from SkyWalking 11.2 — against an older OAP the button is disabled and says what it needs. Nothing is read until the box opens. The lines are searched from 5 minutes before the trace's first span to 5 minutes after its last, at most the trace's last week. Lines from services your role cannot read are left out, and the box says how many. A line is found only if it was stored with the trace id — set by a SkyWalking agent's log reporter, by OAP 11.2 from an OpenTelemetry log record's own trace id and span id, or extracted by a LAL rule. See [A trace's logs](../operate/traces.md#a-traces-logs).

**A log line opens its trace from the right store.** A log row's **↗ trace** link reads the trace from its layer's own trace store — Zipkin on a Zipkin layer, OTLP (through TraceQL) on a layer whose traces are OTLP, the SkyWalking store otherwise — and on **Log inspect** from the store of the picked service's layer (OTLP for a service of **OTLP Service**). When the SkyWalking store holds no spans for the id, the trace overlay offers to query it from the **zipkin** or **traceql-otlp** store instead, where it used to stay empty.

**Click a service in a trace's legend to highlight its spans.** In every trace detail — native, Zipkin and TraceQL, on the trace tabs, on Trace inspect and on the trace overlay — the service legend above the spans now picks a service: its waterfall rows, Tree nodes and Statistics rows take its color, and the first of them is brought into view. The highlight stays while you switch layouts; click the service again, or open another trace, to clear it.

**A layer names its log type, and the Tags field suggests that type's tags.** SkyWalking 11.2 keeps the searchable tags of the logs received over OTLP in one list and those of every other log — SkyWalking agents, Envoy access logs sent through ALS and the rest — in another. A layer template's new `log.type` says which its logs are: `native`, the default when it is absent, or `otlp`. Against SkyWalking 11.2 the **Tags** field on the Logs tab suggests the keys and values of that list only, and on **Log inspect** those of the picked layer's type, or native when no layer is picked. Set it in **Dashboard setup → Layer dashboards**, on the layer's **Logs** tab. The bundled templates of **OTLP Service**, **Agent Router**, **WeChat Mini Program**, **Alipay Mini Program** and **iOS**, whose logs arrive over OTLP, set `otlp`. The tags of OTLP logs stored before the OAP upgrade stay in the other list until they expire. Against an earlier OAP the field reads its single list, as before, and a yellow note at the top of the Logs tab says its suggestions are the tags of every log. An OAP that already stores one of those five templates keeps it without the type, so its Tags field suggests native tags, which its OTLP logs do not carry; to adopt it, open **Dashboard setup → Layer dashboards** for the layer and choose **Reset to → Bundled**, or pick **OTLP** on its **Logs** tab, then **Check diff & push**. See [Layer templates](../customization/layer-templates.md#log).

**The tag field says when something you typed did not make it into the query.** On the native, Zipkin and TraceQL builder trace tabs, pressing Enter on text that is not `key=value` (or, on Zipkin, a bare annotation) leaves it in the field and covers the field with a red note saying so, where it used to be dropped or added without a value. Clicking **Run query** with a tag still in the field runs without it and covers the field with a note for five seconds: press Enter to add it. Typing, or clicking the note, takes it away.

### Fixes

**Tag suggestions stop loading once the browser tab is gone.** On the Traces tab, Trace inspect, the Logs tab and Log inspect, closing or reloading the browser tab while the **Tag** or **Tags** field was still loading its suggestions left Horizon's requests to OAP for those keys and values running until they were answered; Horizon now cancels them. Horizon's own check of what OAP supports, which every page shares, still runs to the end, and a lookup OAP has already started may still finish there.

**The tag fields on the Traces, Logs, Trace inspect and Log inspect pages leave input-method keys to the input method.** Confirming a Chinese, Japanese or Korean candidate with Enter used to add the half-composed text as a tag, and the arrow keys moved through the tag suggestions instead of the candidates.

**A tag value holding a comma keeps its suggestions on the Traces and Logs tabs.** Typing `db.statement=SELECT a, b` used to switch the suggestions back to tag keys after the comma, as if a second tag had started; the field now completes the whole text as one tag. Trace inspect and Log inspect, whose field takes a comma-separated list, are unchanged.

## Alarms

### Fixes

**The Layer, Service, Instance and Endpoint filters on the alarm pages open a readable list.** On Windows, the browser drew their open list white with near-white text, on the default alarm page and on every configured one. They are now the same dropdown the Traces tab's pickers use: a dark list with a filter box to type into. ([apache/skywalking#14211](https://github.com/apache/skywalking/issues/14211))

## Operating Horizon

### Fixes

**Pointing a running Horizon at another OAP checks the new OAP straight away.** After `oap.queryUrl` was changed in a running Horizon's configuration, Horizon kept what it had learned about the previous OAP — which query features it offers and which storage it runs on — for up to five minutes, though the [configuration reference](../setup/horizon-yaml.md) says repointing checks again at once. Against an older OAP this sent queries it rejects, such as a span's **Related logs** and the log tag suggestions, and the **Cold** toggle followed the previous OAP's storage. Both checks now run again on the next request after the address changes.

**After a failed check of the connected OAP, Horizon waits a minute before asking again, even when the check was slow.** Horizon asks OAP which query features it offers and which storage it runs on, and after a failed answer waits a minute before asking again. The minute was counted from when the check began, so a check that took close to a minute or longer to fail — an OAP timing out under a raised `oap.timeoutMs`, or the feature check's several lookups adding up — was repeated by the next page request, adding load to an OAP that was already slow. The minute now counts from when the check ends. The storage check is also asked once at a time, as the feature check already was: when several pages asked together and one OAP node answered slowly, its failure could replace the answer another node had just given and hide the **Cold** toggle.
